# 收藏夹画板整理员（social-favboard-Librarian）

把草稿白板里散落的视频卡片，按用户已经定义好的「体 / 面 / 线 / 点」做语义归类并排版。
本 skill 只做归类与排版，不做采集、不改浏览器扩展、不改 Obsidian 插件源码。

## 何时读我

- 用户要求整理草稿白板、给收藏视频分类、把卡片排成树杈
- 用户要新建、补充、修改一个「体 / 面 / 线 / 点」概念
- 用户问“这条视频属于哪个概念”“为什么放这里”

## 六条铁律

1. **只写一个文件**：插件 `data.json` 里 `targetCanvas` 指向的草稿白板。目标不是它，立即停止并告知用户，绝不写入。
2. **绝不动最终白板**：用户已经整理好的白板一律只读，不扫描、不修改、不删除。
3. **不删除任何用户内容**：不删节点、不删分组、不删连线。唯一允许删除的是本 skill 自己生成、且带 `SF-SHADOW` 标记的影子卡（删除前仍要备份）。
4. **每次写入前备份**：备份放到 skill 工作区 `.sf-out/`，不放在 vault 里（终端对 vault 没有写权限）。
5. **新建文件先征得同意**：新建白板、新建概念库文件前，必须先问用户，得到明确同意才创建。
6. **落盘只能用 Agent 的 edit 工具**：终端里跑的 python 不能写 vault（沙箱限制）。python 只负责读与算，写回由 Agent 用 edit 逐条应用补丁。**禁止用 python 写白板。**

## 概念体系

体 / 面 / 线 / 点由**每个用户在自己的 `分类类型-灵感体系.md` 里定义**，本 skill 不内置任何具体概念。
下表只是示例，实际以用户的概念库为准；首次使用时先引导用户新增自己的第一个体/面。

| 层 | 含义 | 白板上的表达 |
|---|---|---|
| 体 | 互不相干的领域（游戏、财经、AI漫剧） | 最左侧文本卡 |
| 面 | 体下面的维度（游戏玩法、游戏美学、股票、债券） | 一个分组框，框标题就是面名 |
| 线 | 面里的一条脉络/系列 | 框内的小文本节点 |
| 点 | 单条素材 | 一套卡（封面图 + 文本） |

- 允许跳级：体 + 面即可，面下可直接挂套卡。
- 允许后补：线和点可以以后再补，不要求一次定义完整。
- 不画连线，靠位置表达层级，横向从左到右。

## 一套卡

- 一套卡 = 封面图节点（`type: file`）+ 文本节点（`type: text`）。
- 配对规则：同一列，图在上、文在下，`text.y ≈ file.y + file.height + 10`。
- 任何移动、复制、删除都必须**成对**操作。

## 归类规则

1. 一条视频最多复制到 **3 个概念**，3 份内容完全一致。
2. **高置信** → 复制套卡；**中置信** → 只在文本节点**第一行**写「也可归入：X」，不复制；**低置信/判不了** → 不动，留在散卡区。
3. 归属概念 **超过 3 个** → 先出清单让用户确认或删减；**3 个及以下** → 直接执行。
4. 主归属：先比语义匹配度；接近时用层级兜底，**线 > 面**。
5. 已放进分组框的卡视为已分组，不重排；只处理框外散卡。
6. 新建概念后，重扫散卡区，把属于新概念的旧卡排进去。
7. 散卡区只追加、不重排、不额外标注。
8. 永远不静默归类：至少让用户看到一次归属清单。

## 标准流程

### 第 1 步：定位草稿板

```
python scripts/read_config.py [--vault "<vault 路径>"]
```

- 成功输出 `status: ok` + `target_canvas` + `auto_write`
- `need_vault` / `need_choice`：按输出向用户询问 vault，问一次后写回偏好
- `auto_write: true`：提醒用户“建议先关闭『新采集的视频自动写入白板』，避免与本次写入冲突”，得到回应再继续

### 第 2 步：读取白板（只读，可写权限不受限）

```
python scripts/read_canvas.py --canvas "<target_canvas>"
```

输出套卡、分组、散卡的 JSON 摘要。

### 第 3 步：读取概念库

```
python scripts/taxonomy.py --vault "<vault>" --action list
```

概念库默认是 `<vault>/分类类型-灵感体系.md`。不存在时询问用户是否创建，同意后才加 `--confirm`。

### 第 4 步：生成归属提案（由 Agent 判断）

对每一套散卡输出：

```json
{"card_id": "...", "file_id": "...", "title": "...",
 "main": ["游戏", "游戏美学"],
 "copies": [["游戏", "游戏玩法"]],
 "medium": [["财经", "股票"]],
 "reason": "..."}
```

判断依据：标题、作者、平台、话题文字 + 概念库里的描述、关键词、样例标题。不使用封面图。

### 第 5 步：出清单并等待确认

- 任一卡归属 > 3 个概念 → 输出清单，等用户确认或删减
- 有中置信归属 → 告知将写入「也可归入」行
- 其余可直接执行

### 第 6 步：生成完整新白板

```
python scripts/assemble.py --canvas "<target_canvas>" --plan "<plan.json>" --vault "<vault>" --out ".sf-out/organized.canvas"
python scripts/backup.py --canvas "<target_canvas>" --out-dir ".sf-out"
```

- `assemble.py` 只写工作区，**不写 vault**
- 复用已有面框，新卡按每行 3 套排列
- 体按用户概念库里的顺序纵向堆叠
- 先备份当前白板到 `.sf-out`

### 第 7 步：写入白板（唯一方式：生成文件后导入）

生成文件后，让用户在 Obsidian 里执行：

1. `Ctrl + P`
2. 输入 `导入`
3. 选「从 Skill 输出文件导入白板」回车
4. 关掉白板标签页再打开

若插件已开启「Skill整理排版白板-自动覆盖白板（会覆盖用户自己的排版）」，约 2 秒会自动完成，上述步骤可跳过。

**禁止用 python / 终端直接写 vault；禁止用 edit 分批直接改白板。**

### 第 8 步：校验

```
python scripts/verify.py --canvas "<target_canvas>" --backup "<备份路径>" --plan "<plan.json>"
```

- `status: ok` 才算成功
- `coordinate_mismatch` → 重新跑 `assemble.py`
- `pair_mismatch` → 运行 `fixpairs.py` 生成对齐补丁，用 edit 修好后再校验
- `invalid_json` → 用备份恢复并告知用户

**套卡完整性**：每次校验都会检查"每张卡片文本是否有配对的封面图"。出现 `pair_mismatch` 时：

```
python scripts/fixpairs.py --canvas "<target_canvas>" --out ".sf-out/pairs.json"
```

按输出的 `patches` 用 edit 逐条对齐（图片 x 与文本一致、图片放在文本上方、间距 10）；`missing` 表示封面节点真的缺失，需要用户重新采集。

**完成判定（硬规则）**：只有 `verify.py` 返回 `status: ok`，并且重新读取目标白板能读到本次新增的分组框、抽查卡片坐标确实在框内，才可以说“排完了”。否则必须如实说“文件已生成，但白板还没更新”，并说明原因（插件自动写入没开 / 需要手动导入 / 被 Obsidian 覆盖）。禁止用“已完成”“排好了”描述仅生成文件的状态。

### 备用：没有插件时

只有插件不可用时，才退回逐条编辑：

```
python scripts/patch.py --canvas "<target_canvas>" --plan "<plan.json>" --out "<patch.json>"
```

按 `coordinate_patches` 用 edit 逐条替换，再用 `insert_anchor` 插入新节点。

### 第 10 步：生成报告并告知用户（强制，不得省略）

整理结束后**必须主动输出三段式报告，不能等用户索要**。报告是完成流程的一部分，不是可选步骤。

```
python scripts/report.py --canvas "<target_canvas>" --out ".sf-out/report.json"
```

按下面三段式在对话里输出：

**第一段：完成状态 + 已归类**

- 先写：`已完成 · 用时 <X 分 X 秒>`
- 再用表格列出每个概念的张数，最后一行写合计

**第二段：未归类**

- 写未归类总数（`report.json` 的 `loose_total`）
- 按 `clusters` 列出候选概念：名称、数量、2–3 个标题例子

**第三段：推荐新增**

- 给出 1–2 个推荐新增的「体 / 面」组合
- 附新内容的大致坐标范围
- 提醒：Obsidian 关掉草稿板再打开（或重载插件）才能看到新布局

**第四段：本次复制（可选，有复制才写，没有就整段省略）**

- 列出这次被复制到多个概念的视频
- 每条写：标题 → 同时放入哪几个概念 → 共几份
- 没有复制发生时，不写这一段

示例（概念名仅为演示，实际以用户的 `分类类型-灵感体系.md` 为准）：

> 4. 关掉白板标签页再打开

## 禁止事项

- 禁止用 python / 终端写白板
- 禁止写入 `targetCanvas` 以外的任何白板
- 禁止删除用户节点、分组、连线
- 禁止未经同意创建白板或概念库
- 禁止在没有提案的情况下静默归类
- 禁止在 `patch.py` 报 `conflict` 时强行修改
- 禁止把概念库内容放进本 skill 的提交包（那是用户私人数据）
