# Obsidian Canvas 真实格式

本文件记录从用户真实草稿板勘察得到的格式，不要凭文档猜测。

## 文件结构

`.canvas` 是**整体 JSON**，不是按行 JSON：

```json
{"nodes": [ ... ], "edges": [ ... ]}
```

读取时先 `json.loads(全文)`；只有解析失败才回退按行解析。

## 节点类型

### 封面图（file）

```json
{"id": "4240f1f4d5b4f478", "type": "file",
 "file": "video-covers/douyin-7708322062570008680.jpg",
 "x": 10640, "y": 16190, "width": 340, "height": 453}
```

- `file` 是相对 vault 根目录的路径
- 高度随图片比例变化，宽度固定 340

### 文本（text）

```json
{"id": "92d8744069489cde", "type": "text",
 "text": "**标题**\n\n6329 · 抖音\n收录 2026-11-20\n#未分类\n\n[▶ 打开原视频](https://...)",
 "x": 10640, "y": 15043, "width": 340, "height": 176,
 "color": "5"}
```

- `color` 是 Canvas 六色编号："1"红 "2"橙 "3"黄 "4"绿 "5"青 "6"紫
- 卡片身份靠正文里的「打开原视频」链接识别

### 分组（group）

```json
{"id": "cea378ca34b1ee30", "type": "group",
 "x": -11680, "y": -2400, "width": 2260, "height": 1967,
 "color": "2", "label": "one"}
```

- `label` 就是框标题（用于表达「面」）
- 分组靠**坐标覆盖**包含节点，没有父子字段

### 连线（edge）

用户手工画的连线存在 `edges` 数组里，只读，不修改。

## 套卡布局规律

实测（插件默认参数）：

```
file.y
file.height（约 453，随比例变化）
+10        ← 图文间距
text.y
176        ← textHeight
+90        ← 套间间距
下一套 file.y
```

配对规则：

- 同一列（x 相同，容差 2）
- 图在上、文在下
- `0 <= text.y - (file.y + file.height) <= 60` 视为同一套（放宽以兼容手动拖动）

一套卡高度 ≈ `file.height + 10 + textHeight`。

## 列与网格

- 卡片宽度固定 340
- 列间距约 420（340 + gapX 80）
- 插件按网格铺设，散卡可能被用户手动拖乱，配对失败时不要强行配对

## 判断"已分组"

节点（图或文）的矩形只要被某个 group 框覆盖，就视为在组内：

```
node.x >= g.x and node.y >= g.y
node.x + node.width <= g.x + g.width
node.y + node.height <= g.y + g.height
```

一套卡以**文本节点**位置判定所属分组。

## 安全性

- 写回时保持 `{"nodes": [...], "edges": [...]}` 整体结构
- `edges` 原样保留
- 只新增节点或修改自己生成节点的字段；不动用户节点

## 影子卡标记

本 skill 复制出的套卡：
- 文本节点第一行写 `SF-SHADOW:<原文本节点 id>|<概念路径>`（用 HTML 注释包裹，不影响阅读）
- 图片节点文件路径复用原图，不复制图片文件
- 清理时只删除带该标记的节点，删除前仍先备份
